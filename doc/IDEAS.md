# FastFiler 機能アイデアの採否台帳

旧 IDEAS.md (思いつきベースの提案集) を、2026-05-23 のアイデンティティ整理
セッションで採否確定したものに整理し直した台帳。

判断軸は [`/CONTEXT.md`](../CONTEXT.md) の中核アイデンティティ
(B 縦タブ+任意分割ペイン > A 速度 > C Windows 統合 > D 拡張性) に基づく。
個別の重い判断は [`adr/`](./adr/) を参照。

採否ステータス凡例:

- ✅ **採用** — 実装済 (`STATUS.md` §1) または採用予定 (`STATUS.md` §2)
- ❌ **不採用** — 持たない方針 (`STATUS.md` §3)

## 新規アイデア追加ルール

このファイルに新しい機能アイデアを追加する場合:

1. 中核アイデンティティ (`/CONTEXT.md`) の優先順位 (B > A > C > D) と
   照らして「やる価値」を見積もる
2. 採否が明らかでないものは「保留」を作らず、`grill-with-docs` セッションを
   1 回挟んで採否を確定させる (保留状態が長引くと「コード温存負債」につながる
   — ADR 0001 の教訓)
3. 採用と決まった項目は `STATUS.md` §2「採用予定」へ転記し、
   このファイルでは ✅ にする
4. 不採用と決まった項目はこのファイルで ❌ にし、`STATUS.md` §3
   「不採用」表にも 1 行追加する
