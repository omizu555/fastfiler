# ADR 0002: ドックスロットは 1 ヶ所 1 パネルに制限する

- 日付: 2026-05-23
- ステータス: Accepted

## コンテキスト

旧 Tauri 版の USAGE.md では、タブパネル / ワークスペースツリーパネル等を
`左 / 右 / 上 / 下 / 非表示` の 5 ヶ所にドックでき、さらに同位置に複数パネルが
来た場合の挙動を「並列表示 / 積み重ね」設定で切り替えられる仕様になっていた。

現行 floem 版では `left / right / hidden` の 3 ヶ所のみ対応。
ターミナル (IDEAS.md #16「やる」) など将来パネルが増えることを見据え、
ドック仕様をここで確定させる必要があった。

## 検討した選択肢

1. **A. USAGE.md 通り 5 ヶ所 + 並列/積み重ね切替** (フル機能)
2. **B. 5 ヶ所対応するが「同位置複数」は禁止** (1 dock = 1 パネル)
3. **C. 現状維持** (左 / 右 / 非表示の 3 ヶ所)

## 決定

**B を採用** — ドック位置は 5 ヶ所 (`left / right / top / bottom / hidden`) に
拡張するが、**各 dock スロットには常に高々 1 パネルだけ** が入る。

すでに別パネルが入っている位置に新たなパネルを移動させた場合は、
既存パネルを `hidden` に追い出す (置換) か、ユーザーに別位置を選ばせる。

## 理由

- **縦タブをコアに据えている**ため、タブパネルを上/下に置くケースはほぼない。
  一方でワークスペースツリーやターミナルを下に置きたいケースは現実的にある。
  上下対応自体には意味がある
- 「同位置に複数 + 並列/積み重ね切替」は 1 つの設定で挙動が 2 通りに分岐し、
  ユーザーのメンタルモデルが一気に複雑になる。1 dock 1 パネル制約なら
  「左にタブ、右にツリー、下にターミナル」のように位置と内容が 1 対 1
- ターミナル (IDEAS #16) など将来追加されるパネルも、同じ dock 機構で
  対称的に扱える (「ターミナルは下にしか置けない」のような特殊扱い不要)

## 結果

- 永続化スキーマ: dock スロット → パネル ID の 1 対多ではなく 1 対 1 で持つ
- UI: ドックボタンは `◧ / ◨ / ⬒ / ⬓ / ✕` の 5 種
- 「同じ位置に複数あるとき 縦/横に積み重ねる」設定は **存在しない**
  → USAGE.md からも該当記述を削除
- 将来「下に複数パネルを縦に並べたい」要望が出た場合は、本 ADR を再検討する
  (タブ式の dock コンテナを導入する案など)
