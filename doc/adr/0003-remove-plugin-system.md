# ADR 0003: プラグイン機構を削除し、拡張点はユーザーコマンド + シェル統合に一本化する

- 日付: 2026-05-23
- ステータス: Accepted

## コンテキスト

旧 Tauri + Solid.js 版には、JavaScript ベースのプラグイン機構があり
(`plugin-host.ts`、`%APPDATA%\fastfiler\plugins\<id>\`)、USAGE.md §11 に
詳細仕様が記載されている。floem (Rust 純) 版にもその名残として
`fastfiler-domain/src/plugin.rs` (将来用) が残っている。

IDEAS.md #18「プラグインマーケット」は「やる」とマークされていた一方、
ユーザーは `CONTEXT.md` の中核アイデンティティで**拡張性を最低優先 (D)** と
位置付けている。また、現実的な拡張点として以下がすでに揃っている:

- **ユーザーコマンド** (`commands.json`) — 任意の外部コマンドを右クリック追加可
- **ホットキー** — 26 アクションをユーザー設定可能
- **テーマ / アイコンセット / フォント** — UI カスタマイズ
- **(計画中) IContextMenu 統合** (IDEAS #20)
- **(計画中) 外部ターミナル起動** (IDEAS #16 の方針転換)

## 検討した選択肢

1. **A. 本気で実装** — WASM プラグインホスト + マーケット UI
2. **B. 完全削除** — `domain/plugin.rs` を消し、USAGE §11 / IDEAS #18 も廃止
3. **C. 保留 (Park)** — コードは残し UI 露出だけ封じる

## 決定

**B を採用** — プラグイン機構の概念ごと削除する。

含むもの:

- `fastfiler-domain/src/plugin.rs` の削除 (および呼び出し箇所)
- USAGE.md §11「プラグイン」の削除
- IDEAS.md #18「プラグインマーケット (ローカル)」を不採用に変更
- `doc/plugins-sample/` の扱いは別途検討 (削除またはアーカイブへ移設)

代わりに **拡張点は 3 軸に一本化** する:

1. **ユーザーコマンド** (`commands.json`) — アプリ内拡張
2. **シェル統合** (IDEAS #20 IContextMenu) — Windows エコシステムを借りる
3. **テーマ / ホットキー / アイコンセット** — UI/UX カスタマイズ

## 理由

- 中核アイデンティティで拡張性を最低優先と確定したため、WASM ホストのような
  大物への投資余地が薄い
- ユーザーコマンドが事実上の拡張点として既に機能している
  (VSCode で開く / 7-Zip 圧縮 / ここで PowerShell 等が `commands.json` で書ける)
- IContextMenu を実装すれば、圧縮ツール・Git GUI・クラウド同期等は
  **Windows シェル拡張のエコシステムをそのまま流用**できるため、
  自前プラグインホストを持つ意味がさらに薄れる
- 「保留 (C)」は ADR 0001 (ペイン連動) で否定したのと同じ「コード温存」状態を
  生み出すため避ける

## 結果

- プラグイン関連のメンテナンス負債が消え、`fastfiler-domain` のスコープが
  「OS / ファイル操作ライブラリ」に純化される
- 「FastFiler を拡張したい」ユーザーは `commands.json` を編集する経路に統一される
- 将来「アプリ内 UI を拡張したい」要望が出た場合は、本 ADR を再検討する
  (その時点では WASM 環境やシェル統合の成熟度も変わっているはず)
