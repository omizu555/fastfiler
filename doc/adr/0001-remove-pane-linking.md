# ADR 0001: ペイン連動 (連動 Red / Blue) を完全削除する

- 日付: 2026-05-23
- ステータス: Accepted

## コンテキスト

旧 Tauri 版から引き継いだ「ペイン連動」機能が現在中途半端な状態にある:

- `STATUS.md` 上「連動動作・ツリーボタン・ペイン名」は **UI 上は非表示化済 / コードは温存**
- `USAGE.md` には 🔴連動Red / 🔵連動Blue の概念が記載されたまま
- ワークスペースツリーの「反映先」プルダウンや IDEAS.md #11「同期スクロール」もこの機能に依存している

この宙ぶらりんな状態が、以下の決定を保留状態にしていた:

- ワークスペースツリーの「反映先」UI の仕様
- 同期スクロール (IDEAS #11) の実装単位
- フォーカスペインとの責務分担

## 検討した選択肢

1. **A. フル復活** — Red/Blue マーク + 同色ペイン同士でのフォルダ移動同期、同期スクロール込みで実装
2. **B. 簡易版だけ復活** — フォーカスペイン追従のみ残し、Red/Blue 概念は削除
3. **C. 完全削除** — UI 非表示中のコードも消し、概念ごと無くす

## 決定

**C を採用** — ペイン連動の概念ごと完全削除する。

含むもの:

- 「連動 Red / Blue」のペインマーク機能
- 「反映先」プルダウン (アクティブ / Red / Blue) の概念
- 関連する温存コード (`PaneState` の連動関連フィールド、UI 非表示要素)
- USAGE.md 上の関連記述
- IDEAS.md #11「同期スクロール」も連動機構に乗せる前提だったため、本決定と同時に **不採用** とする
  (左右ペインの汎用同期スクロールとしての再提案は将来の検討事項)

フォーカスペインの概念は残す (ホットキーやツリークリックの宛先決定に必須)。

## 理由

- FastFiler のコアアイデンティティは「縦タブ + 任意分割ペイン」(`CONTEXT.md` 参照)。
  **作業文脈の切り替えはタブで行う**モデルなので、同一タブ内に Red/Blue を別文脈として持つのはタブの存在意義と重複する
- IDEAS.md でも同じロジックが採用済み (#1「クイックアクセス → タブで代替」「やらない」)
- 「コード温存・UI 非表示」状態が最悪 (動かないコードがメンテ負債になる)
- 簡易版 (B) も「フォーカスペイン追従」と機能的に等価で、概念を 2 つに増やす意味が薄い

## 結果

- 実装: `PaneState` ほかの連動関連コードを削除、UI 非表示要素を撤去
- ドキュメント: USAGE.md / STATUS.md / IDEAS.md から連動関連記述を削除
- 将来「左右ペイン汎用の同期スクロール」を再提案する場合は、Red/Blue ではなく
  「分割ペアに対する一時的なリンク」として別途設計する
