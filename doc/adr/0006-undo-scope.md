# ADR 0006: Undo の対象は破壊しない操作 (リネーム / 移動 / ゴミ箱送り) に限定する

- 日付: 2026-05-23
- ステータス: Accepted (2026-06-07 に乖離解消 — 3 種すべて配線済み)

## コンテキスト

IDEAS.md #4「ファイル操作の Undo」は「やる」とマークされ、対象として
「リネーム / 移動 / コピー / ゴミ箱送り」が挙げられていた。実装にあたり
どの操作を Undo 対象にするかを確定させる必要があった。

各操作の Undo は次のような性質を持つ:

| 操作 | Undo の中身 | リスク |
|---|---|---|
| リネーム | 元の名前に戻す | なし |
| 移動 | 元のフォルダに戻す | なし |
| ゴミ箱送り | ゴミ箱から復元 | 復元失敗の可能性 (同名衝突等)、データ自体は失われない |
| コピー | **コピー先ファイルを削除** | コピー後に編集されていた場合、編集内容を破壊する |

## 検討した選択肢

1. **A. フル実装** (4 種すべて)
2. **B. リネーム + 移動 のみ**
3. **C. 不採用**
4. **D. ゴミ箱送りだけ Undo (= ゴミ箱から戻す)**
5. **B + D** (リネーム / 移動 / ゴミ箱送り)

## 決定

**B + D を採用** — Undo 対象は **リネーム / 移動 / ゴミ箱送り** の 3 種に限定し、
**コピーは対象外**とする。

仕様:

- 履歴は in-memory、N = 20、起動間で保持しない
- ゴミ箱送りの Undo は復元失敗 (同名衝突等) があり得る → 失敗時はダイアログで通知し、
  「ゴミ箱を開く」導線を提示
- Undo できる操作が履歴に無い状態で Ctrl+Z を押した場合は、
  ステータスバーに「Undo できる操作がありません」を短時間表示
  (静かに無反応より、入力が認識されたことが分かる方が親切)

## 理由

- **コピーの Undo は破壊的**: ユーザーがコピー後にコピー先ファイルを編集していた
  場合、Undo によって編集内容が永久に失われる。「Undo」の名のもとに
  データを破壊する操作は信頼を損なう
- リネーム / 移動 / ゴミ箱送りはいずれも **元データが残っている** 操作なので、
  Undo してもデータ損失は発生しない (ゴミ箱送りは復元失敗があり得るが
  「失敗してデータが残る」方向の失敗)
- 「Ctrl+Z でコピーを取り消したい」要望が出た場合は本 ADR を再検討する
  (その場合「コピー先が未変更であることを確認してから削除」のような
  サポート条件を設計に含める必要がある)

## 結果

- Undo マネージャは 3 種類の操作型のみ扱えばよく、実装/テストがコンパクト
- ユーザーは「Undo は破壊しない操作だけに効く」というメンタルモデルを持てる

## 追記 (2026-06-07) — GPUI 版の実装状況

- **3 種すべて配線済み** (同日中に乖離解消): リネーム / ゴミ箱送りに加え、
  移動 (D&D / 切り取り→貼り付け / 右ボタン「ここに移動」) もジョブ完了時に
  履歴へ積まれる (`pane.rs` の `pending_move_undo`)。
- 制約: 移動ジョブはアイテム別の成否を返さないため、**全件成功した移動だけ**
  記録する (失敗 / キャンセルした移動は Undo 不可 — 誤った履歴を作らない安全側)。
