# 0010. 右ボタン D&D メニュー — スコープを「内部 + 外部受信」に限定

- 状態: 採用
- 日付: 2026-05-23

## 背景

Windows エクスプローラには右ボタンでファイルをドラッグすると、ドロップ時に
「ここにコピー / ここに移動 / ここにショートカットを作成 / キャンセル」
メニューが出る機能がある。FastFiler でも同等の操作感を求める要望があり、
STATUS.md §1 に未実装項目として登録されていた。

実装に際してスコープを決める必要があった。技術コストが大きく異なる 3 経路:

1. **内部 D&D** (FastFiler ペイン間) — floem の PointerEvent でボタン判別、
   既存の内部 D&D に分岐を足すだけ。低コスト。
2. **外部受信** (Explorer → FastFiler) — `IDropTarget::Drop` の `grfKeyState` の
   `MK_RBUTTON` を見て判別 → 自前メニュー表示。中コスト。
3. **外部送信** (FastFiler → Explorer) — `DoDragDrop` を右ボタン押下中に呼べば
   Windows が右ボタンモードで回し、Explorer 側がメニューを出すはずだが、
   送信側 (#D Phase 1) が現状左ボタン専用 PointerMove で start_drag を呼ぶ
   構造であり、両ボタン対応への拡張は送信側のリファクタも必要。

## 決定

今回は **「内部 + 外部受信」のみ** を実装する。**外部送信は将来タスク**として
分離する。

メニュー項目は **3 項目** (`ここにコピー` / `ここに移動` / `キャンセル`) とする。
ショートカット (.lnk) 作成は FastFiler に未実装機能であり、メニューに含めない。

## 採用理由

- 内部 + 外部受信は既存コードへの影響範囲が限定的で、独立して価値を提供できる。
- 外部送信は送信側 D&D 全体のリファクタが絡み、影響範囲が大きい。
  別タスクとして切り出した方が PR レビューも検証も明快。
- ショートカット作成は別機能 (右クリックメニューやアクション体系) と整合性を取って
  設計すべきで、本タスクに巻き込むとスコープが不明瞭になる。

## 結果

- pane.rs の内部 D&D に「右ボタンモード」フラグを追加、PointerUp 時に
  `floem::menu::Menu` でコンテキストメニュー表示。
- `CDropTarget` callback で受け取る `key_state` から `MK_RBUTTON` を判別し、
  外部受信時もメニューを出す。
- 同一フォルダドロップは左ボタン D&D と同じく無視 (メニューも出さない)。
- 右ボタン D&D 中の Ctrl/Shift は無視 (メニュー選択が最終決定)。

## 代替案と却下理由

- **3 経路同時実装**: 外部送信側の D&D は左ボタン PointerMove 起動で構造が
  噛み合わず、リファクタ込みになる。スコープ肥大で却下。
- **メニュー 4 項目 (ショートカット含む)**: ショートカット作成機能自体が未実装。
  別タスクで実装後に項目追加すべき。
