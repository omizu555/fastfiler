# ADR 0004: 内蔵ターミナルを持たず、外部ターミナル起動に一本化する

- 日付: 2026-05-23
- ステータス: Accepted

## コンテキスト

旧 Tauri 版は xterm.js + 内蔵 PTY による内蔵ターミナルパネルを dock 機構の上に
載せる構想だった (IDEAS.md #16「やる」)。floem 版にもその準備として
`fastfiler-domain/src/term.rs` (portable-pty ラッパ) が温存されている。

一方、ADR 0003 で「拡張点は `commands.json` + シェル統合 + テーマ/ホットキー
の 3 軸に一本化する」と決定済み。ユーザーコマンドのサンプルにはすでに
「ここで PowerShell」が含まれており、外部ターミナルを cwd 付きで起動する経路は
**今日すでに動作している**。

## 検討した選択肢

1. **A. 内蔵ターミナルを実装** — dock パネル + 自前ターミナルエミュレータ
2. **B. 外部ターミナル起動のみ** — `wt -d {cwd}` 等をホットキー/コマンドで起動
3. **C. ホットキー + 設定ダイアログ専用 UI** — 起動コマンドを設定で選べる

## 決定

**B を採用** — 内蔵ターミナルは持たず、外部ターミナル起動に一本化する。

含むもの:

- `fastfiler-domain/src/term.rs` の削除
- USAGE.md §10「ターミナル」を「外部ターミナル起動」の節に書き換え
- IDEAS.md #16 を「外部起動のみ・内蔵廃止」と明示
- 既定の `commands.json.sample` に「ここで Windows Terminal」「ここで PowerShell」
  を含める

将来「外部ターミナルを cwd で開く」ホットキーを 1 つ追加することは妨げない
(ユーザーコマンド経由でなくキー一発で起動できる利便性のため)。
ただし内蔵 PTY やターミナルエミュレータは持たない。

## 理由

- ADR 0003 で拡張軸を絞った直後に内蔵ターミナルを抱えると、
  PTY + ANSI レンダラ + 入力レイヤ + dock パネル UI を新規に背負うことになる。
  コア (縦タブ + 任意分割ペイン) と無関係な大物機能であり、優先順位に合わない
- `commands.json` で 1 行書けば 95% のニーズに応えられる
- C (専用 UI) は結局「ターミナル設定タブ」を作ることになり、
  ADR 0003 の「拡張は `commands.json` に集約」原則に逆行する
- `term.rs` を残すと ADR 0001 と同じ「コード温存負債」を再生産する

## 結果

- `fastfiler-domain` から PTY 依存 (portable-pty crate) が消える
- ターミナルに関する UI は **存在しない** (`Ctrl+\` のような dock 切替ホットキーも廃止)
- 「内蔵ターミナルを再導入したい」要望が出た場合は本 ADR を再検討する
