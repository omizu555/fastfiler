# ADR 0007: シェル拡張メニューは Shift+右クリックでのみ呼び出す

- 日付: 2026-05-23
- ステータス: Accepted

## コンテキスト

ADR 0003 で「拡張点はユーザーコマンド + シェル統合 + テーマ/ホットキーの
3 軸に一本化する」と決定。「シェル統合」の中身を IDEAS.md #20
「ネイティブ IContextMenu 統合」をベースに具体化する必要があった。

`IContextMenu` のフル統合は実装が非常に重い:

- `IShellFolder` 連鎖、PIDL ハンドリング、サブクラス化
- 各シェル拡張の癖 (壊れたインストールでアプリ全体がクラッシュ等) への耐性
- ADR 0001 のクラッシュ耐性方針 (例: `IFileOperation` ではなく `SHFileOperationW`
  を採用) と相性が悪い

## 検討した選択肢

1. **A. フル統合** — 右クリックで Windows 標準と同等のメニュー
2. **B. 「Open With」+ 標準動詞のみ** — Windows 標準動詞だけネイティブ再現、
   サードパーティ拡張は呼ばない
3. **C. Shift+右クリックで Windows 標準メニューに丸投げ** — 通常右クリックは
   FastFiler の軽量メニュー、Shift+右クリックで `IContextMenu` 呼出
4. **D. 不採用** — シェル拡張は呼ばない

## 決定

**C を採用** — 通常の右クリックは FastFiler が完全制御する軽量メニュー
(ユーザーコマンド + 内蔵動作) を表示し、**Shift+右クリック** で
選択ファイルに対する Windows シェル拡張メニュー (`IContextMenu`) を表示する。

仕様の骨子:

- 通常右クリックメニューの構成:
  「開く / プログラムから開く / 切り取り / コピー / 貼り付け / リネーム /
   削除 / 新規 / プロパティ / ユーザーコマンド / Windows メニュー…」
- 「Windows メニュー…」を選ぶ動作は Shift+右クリックと同等
- Shift+右クリックメニューはなるべく Windows エクスプローラと同じ見た目
  (FastFiler 側で項目を間引かない)
- シェル拡張のクラッシュは FastFiler 本体を巻き込まないよう、可能な範囲で
  分離して呼び出す (具体策は実装時に検討)

## 理由

- フル統合 (A) はクラッシュ耐性方針と衝突。「ファイラが落ちる」のは致命的
- B は「標準動詞は出るのに 7-Zip が出ない」という中途半端な状態になり、
  ユーザーは「壊れている」と感じる
- C なら通常メニューは高速・安定・カスタマイズ可、シェル拡張が必要なときは
  Shift+右クリックで「Windows 標準に逃げる」エスケープハッチがある
- C の実装は `IContextMenu` 呼出 + ポップアップ表示で済み、フル統合より
  桁違いに軽い
- D は IDEAS #20「やる」と Windows 統合 (中核アイデンティティの優先 C) を弱める

## 結果

- 通常メニューは `core::actions` + `commands.json` のロジックのみで完結
- Shell 統合は `fastfiler-domain` の新規モジュール
  (例: `shell_context_menu.rs`) に隔離
- 「右クリックで常に Windows 標準を出してほしい」要望が出た場合は、
  設定で「常に Shift と同じ振る舞い」を有効化する option を検討する余地はある
  (ただし規定値は本 ADR の通り)
