# ADR 0005: メディアプレビュー (サムネイル / プレビューペイン) を持たない

- 日付: 2026-05-23
- ステータス: Accepted

## コンテキスト

旧 Tauri 版にはサムネイル一覧表示とプレビューペインがあり、現行 floem 版にも
コード資産として残っている:

- `fastfiler-domain/src/thumbnail.rs` (IShellItemImageFactory + LRU)
- `fastfiler-domain/src/preview.rs` (画像 / テキストプレビュー)

両者とも STATUS.md では「未実装 (旧 Tauri 版にあった機能)」扱い。
IDEAS.md #14「クイックビュー (Spacebar)」もユーザー判断で「やらない」と
マークされており、「プレビューを見たい衝動はあるが、コア価値ではない」という
方向性は出ていた。

## 検討した選択肢

(a) サムネイル / (b) プレビューペイン それぞれ独立に判断:

1. **実装する** — UI を作って一覧モード/dock パネルとして提供
2. **削除する** — 該当する domain コードを消し、機能不採用と明示

## 決定

**両方とも「削除する」を採用** — FastFiler はメディアプレビュー機能を持たない。

含むもの:

- `fastfiler-domain/src/thumbnail.rs` の削除 (および呼び出し箇所)
- `fastfiler-domain/src/preview.rs` の削除 (および呼び出し箇所)
- STATUS.md の未実装一覧から両者を除外 (=「不採用」として明示)
- USAGE.md §9.1「サムネイル」/ §9.2「プレビュー」を削除
- IDEAS.md #14「クイックビュー」も不採用のまま維持

## 理由

- 中核アイデンティティは「縦タブ + 任意分割ペインで大量フォルダを操作」であり、
  **写真/メディア整理用ファイラではない**
- 写真整理や PDF 確認は専用ビューア (Honeyview, SumatraPDF 等) を
  `commands.json` から起動する方が体験が良い (ADR 0003 の方針と整合)
- プレビューペインは ADR 0002 の「1 dock 1 パネル」原則のもとで
  コアの作業領域を圧迫する
- `thumbnail.rs` / `preview.rs` の温存は ADR 0001 / 0003 / 0004 と同じ
  「コード温存負債」の再生産

## 結果

- `fastfiler-domain` から画像/プレビュー処理コードが消え、責務が
  「ファイル一覧・操作・監視・検索」に集約される
- 「サムネイル一覧モード」「プレビューペイン」「Quick Look 風モーダル」のいずれも UI に存在しない
- 将来サムネイルを再導入したい要望が出た場合は本 ADR を再検討する
  (その場合は専用ビューア起動との優位性を改めて評価する)
